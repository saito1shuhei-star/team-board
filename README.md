# Team Board

チャットに流れていく進捗報告を読んで、**いま何が止まっていて、誰の手が空いていて、今日それを誰に振れるか**を1枚に映す作業板です。

学生プロジェクト（人力飛行機チーム）での運用を想定して作りました。
**人は何も入力しません。** チャットの投稿を貼るだけです。

**[→ デモを見る](https://saito1shuhei-star.github.io/team-board/)**

> このリポジトリに入っているのは**架空のサンプルデータ**です。実在の団体・個人の情報は含みません。

---

## なぜ作ったか

班長が5人、班員が十数人いるチームで、こういうことが起きていました。

- 班長自身も設計のやり方を調べながら手順を作っている段階で、**手いっぱいで班員に指示を出せない**
- その結果、**班員の手が空いたまま**になる
- 一方でPMは各班に個別に催促して回っている
- 上流の1班が止まると下流の複数班が止まるが、**誰もその連鎖を把握していない**

問題は「進捗が見えないこと」そのものではなく、**進捗が見えないせいで仕事を切り出せないこと**でした。
だからこの板は、状況を映すだけでなく **D「今すぐ振れる調査タスク」** まで出します。

---

## 何が出るか

| | 内容 |
|---|---|
| **タイル** | 締切までの日数、超過日数、止まっている件数、図面まで到達した成果物の数 |
| **締切** | マイルストーンと残り日数。超過は赤 |
| **班と班のつながり** | 依存グラフ。矢印は「元 → 待っている先」。丸の色＝最終報告からの経過日数。上流が止まると何班に波及するかを表示 |
| **進行度** | 成果物の到達段階を積み上げ棒で。**%ではなく件数** |
| **A 動いている** | 進行中の作業と最終更新日 |
| **B 止まっている** | 経過日数の長い順。`他班待ち / 外部待ち / 判断待ち / 放置` に分類 |
| **C 登場していない** | 直近7日、報告に出てこない役職 |
| **D 振れるタスク** | そのままチャットに貼れる依頼文＋コピーボタン |

## 設計上、意図的にやっていないこと

**進捗率（%）を推測しない。**
本人が申告した数字以外は扱いません。AIが「この作業は60%完了」と推定した瞬間に、板は信用されなくなります。
代わりに、成果物が `未着手 → 検討中 → 数値・方針あり → 図面あり → レビュー済` のどの段階かを数えます。数えているだけなので嘘になりません。

**人を評価しない。**
Cは「余力あり」「稼働なし」とは書きません。「直近7日、報告に登場していません」という事実だけを書きます。
サボっていると読める書き方をすると、吊るし上げの道具に見えて誰も使わなくなります。

**ログにない情報を書かない。**
読み取れない項目は「記載なし」。前後関係から補った箇所には「推定」と明記します。

## 使い方

### そのまま見る

`index.html` をダウンロードしてダブルクリックするだけです。ビルドもサーバーも要りません。
外部ライブラリは読み込んでいません（Webフォントのみ）。

### 自分のチームのログで動かす

1. チャットの進捗報告をテキストで用意する（下の形式）
2. `PROMPT.md` の中身をコピーして、生成AI（Claude / ChatGPT など）に貼る
3. 続けてログを貼る
4. 出てきたHTMLを保存する

ログの形式は緩くて構いません。日付・発言者・本文が読み取れれば十分です。

```
2026-08-04 駆動班長
先日報告した軸径だと合う歯車が見つからなかったため決定し直しました。

2026-08-05 駆動班長
今班員に与えられる仕事が思いつかないため各自調べ学習を行ってください。
```

### 生成後の更新

**「新しい投稿を貼って更新する」** を開いて `2026-08-27 翼班長` のように「日付 役職」で始まる行を貼ると、
最終登場日・経過日数・グラフの色がブラウザ内で再計算されます。生成し直す必要はありません。

基準日を変えれば、その日時点の板になります。
