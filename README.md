# Team Board

チャットに流れていく進捗報告を読んで、**いま何が止まっていて、誰の手が空いていて、今日それを誰に振れるか**を1枚に映す作業板です。

学生プロジェクト（人力飛行機チーム）での運用を想定して作りました。
**人は何も入力しません。** チャットの投稿を貼るだけです。

**[→ デモを見る](https://saito1shuhei-star.github.io/team-board/)**

> このリポジトリに入っているのは**架空のサンプルデータ**です。実在の団体・個人の情報は含みません。

---

## なぜ作ったか

班長が5人、班員が十数人いるチームで、こういうことが起きていました。

- 班長自身も設計のやり方を調べながら手順を作っている段階で、**手いっぱいで班員に指示を出せない**
- その結果、**班員の手が空いたまま**になる
- 一方でPMは各班に個別に催促して回っている
- 上流の1班が止まると下流の複数班が止まるが、**誰もその連鎖を把握していない**

問題は「進捗が見えないこと」そのものではなく、**進捗が見えないせいで仕事を切り出せないこと**でした。
だからこの板は、状況を映すだけでなく **D「今すぐ振れる調査タスク」** まで出します。

---

## 何が出るか

**班ではなく「設計値」を単位にして、値と値のあいだの依存を追います。**

| | 内容 |
|---|---|
| **タイル** | ブロッカー / 停止中 / 仮置き / 作業中 / 確定 の件数。クリックで絞り込み |
| **依存関係** | 設計値の依存グラフ。上流→下流を自動レイアウトで配置 |
| **一覧** | 設計要素・担当・現在値・状態・停滞日数 |
| **変更履歴** | 何が変わって、何に影響したか |
| **振れる仕事** | そのままチャットに貼れる依頼文＋コピーボタン |
| **右パネル** | 選んだ要素の見直し条件・影響範囲・上流・根拠 |

### 状態は4つ

`確定 / 作業中 / 仮置き / 停止中`

**「仮置き」を独立させているのが肝です。** 根拠なく置いた値と、確定した値を混ぜません。仮置きの要素には**見直し条件**を持たせます（例：機体抗力が確定したら再計算する）。

### 3種類の警告を出し分ける

| 警告 | 意味 |
|---|---|
| **再確認が必要** | 上流が自分より後に更新された → 自分の値を見直す |
| **上流が止まっている** | 上流が停止中 → そもそも確定できない |
| **記録が古い可能性** | その班にチャットで新しい投稿がある → 板の記録が追いついていない |

どれも**日付を比べているだけ**で、推定はしていません。

### 値の再計算はしません

「この値を変えたらいくつになるか」は出しません。桁の荷重計算などは材料力学の計算が要り、AIに推定させると**間違った強度が出ます。人が乗る機体なので、そこは線を引いています。**

出すのは**影響範囲の列挙**までです。「この値が変わると再確認が必要になる要素」と「さらに先まで含めると◯要素に波及します」。

## 使い方

### そのまま見る

`index.html` をダウンロードしてダブルクリックするだけです。ビルドもサーバーも要りません。
外部ライブラリは読み込んでいません（Webフォントのみ）。

### 自分のチームのログで動かす

1. チャットの進捗報告をテキストで用意する（下の形式）
2. `PROMPT.md` の中身をコピーして、生成AI（Claude / ChatGPT など）に貼る
3. 続けてログを貼る
4. 出てきたHTMLを保存する

ログの形式は緩くて構いません。日付・発言者・本文が読み取れれば十分です。

```
2026-08-04 駆動班長
先日報告した軸径だと合う歯車が見つからなかったため決定し直しました。

2026-08-05 駆動班長
今班員に与えられる仕事が思いつかないため各自調べ学習を行ってください。
```

### 生成後の更新

更新方法は3段階あり、上から順に自動で試します。

| | 方法 | 反映 |
|---|---|---|
| ① | `server.mjs` に SSE 接続 | **投稿した瞬間** |
| ② | `log.txt` を10秒ごとに読む | データ元の更新から10秒以内 |
| ③ | どちらも取れなければ静的表示 | — |

サーバーが居なければ②へ、ファイルも取れなければ③へ自動で落ちます。
基準日を変えれば、その日時点の板になります。

**自動で更新されるのは「記録が古い可能性」の警告だけです。**
チャットの本文から設計値の状態を自動判定することはしていません。班に新しい投稿があったことを検知して、人に確認を促すところまでです。
設計値そのものを更新するには、`index.html` 冒頭のデータ配列を直すか、`PROMPT.md` で作り直します。

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | 板の本体。単一ファイル、依存なし |
| `server.mjs` | Discord と直接つなぐサーバー（推奨の使い方） |
| `scripts/sync-discord.mjs` | GitHub Actions 用の定期同期スクリプト |
| `sync.config.example.json` | チャンネルIDと役職表のひな形 |
| `PROMPT.md` | 自分のログからHTMLを生成するためのプロンプト |
| `sample-log.txt` | サンプルデータの元になった架空のログ |

## Discord と直接つなぐ（推奨）

Bot を常時接続させて、**投稿された瞬間に板へ push** します。中間ファイルも GitHub Actions も要りません。

```
Discord Bot（Gateway 常時接続）
  → 投稿された瞬間に受信
  → 同じプロセスが板も配信
  → SSE でブラウザへ push
  → 即座に反映
```

### 動かし方

```bash
npm install
cp sync.config.example.json sync.config.json   # チャンネルIDと役職表を書く
```

```bash
# bash
DISCORD_BOT_TOKEN=... npm start
```
```powershell
# PowerShell
$env:DISCORD_BOT_TOKEN="..."; npm start
```

`http://localhost:8787/` を開くとヘッダに **「● Discord接続中（即時反映）」** と出ます。
Discordに投稿すると、リロードなしでその場で板が変わります。

起動時に各チャンネルの直近30件を取り込むので、立ち上げた瞬間から埋まった状態になります。

### 置き場所

常時動いている必要があります。用途に合わせて選んでください。

| 置き場所 | 向き |
|---|---|
| 部室のPC / ラズパイ | 部内から見るだけならこれで十分。無料 |
| Fly.io / Railway など | 外からも見たいとき |
| 手元のPC | 動作確認・デモ用 |

### 注意

サーバー方式では**本文つきで配信します**（`includeBody` の既定が true）。
起動時にも警告が出ますが、**この URL を外部に公開しないでください。**
本文を出したくない場合は `sync.config.json` で `includeBody: false` にしてください。

## Discord からの定期同期（GitHub Actions・サーバーを置けない場合）

常時稼働させる場所が無い場合の代替です。15分ごとに `log.txt` を更新し、板がそれを10秒ごとに読みます。

**サーバーは不要**ですが、反映は最大15分遅れます。即時性が要るなら上の「直接つなぐ」を使ってください。

```
GitHub Actions（15分ごと）
  → Discord API でチャンネルのメッセージを取得
  → log.txt を書き換え
  → 変更があればコミット
  → Pages が再ビルド
  → 開いている板が10秒以内に自動で拾う
```

### 個人情報を出さない設計

公開リポジトリなので、既定では **`日付` と `役職` しか書き出しません**。本文もDiscordの表示名も出ません。
板のポーリングは `YYYY-MM-DD 役職` の行しか読んでいないので、これで動きます。

- Discordのユーザー ID → 役職名 の対応表（`sync.config.json` の `roles`）で置き換える
- 対応表に無い人は `メンバー` になる（実名は出ない）
- 本文を含めたい場合は `includeBody: true`。ただし **その場合はリポジトリを private にしてください**
- メンションと URL は自動で除去される

### 設定手順

自分でやる必要があるのは次の4つです。**トークンは誰にも渡さず、GitHubの画面から直接登録してください。**

**1. Bot を作る**
[Discord Developer Portal](https://discord.com/developers/applications) → New Application → Bot → Reset Token でトークンを取得。
Bot の設定で **Message Content Intent を ON** にする。

**2. Bot をサーバーに招待する**（サーバー管理者の権限が必要）
OAuth2 → URL Generator → scope に `bot`、権限に `View Channels` と `Read Message History` だけを選ぶ。
生成された URL を開いて招待する。**それ以外の権限は付けないこと。**

**3. トークンを GitHub に登録する**
リポジトリの Settings → Secrets and variables → Actions → New repository secret
- Name: `DISCORD_BOT_TOKEN`
- Secret: 手順1で取得したトークン

**4. 設定ファイルを作る**
```bash
cp sync.config.example.json sync.config.json
```

`channels` に読み取るチャンネルのIDを書く。IDは、Discordでそのチャンネルを開いたときのURL末尾の数字。

役職の対応表は2通りあります。

| 書き方 | 手間 | 確実さ |
|---|---|---|
| `rolesByName`（**推奨**） | 表示名を書くだけ | 表示名を変えると外れる |
| `roles` | ユーザーIDが要る | 名前を変えても外れない |

`rolesByName` は表記ゆれを吸収します。`亀井 達朗` と登録しておけば、`亀井達朗`・`亀井　達朗`・`亀井 達朗 [タグ]` のどれでも当たります。

**実行すると、どちらの表にも無い人が警告で出ます。** それを見ながら追記していけば埋まります。

```
役職表に無い人が 2 名います（"メンバー" として出力しました）:
  - 小松 雄太
  - 前田 悠惺
```

> `sync.config.json` は `.gitignore` に入っています。チャンネルIDやユーザーIDが公開されないためです。
> Actions で使う場合は、このファイルの中身を Secret（例: `SYNC_CONFIG`）に入れてワークフローで書き出すか、
> リポジトリを private にしてコミットしてください。

### 動作確認

Actions タブ → Sync Discord to log.txt → Run workflow で手動実行できます。
トークンが未設定でも**エラーにはならず**、`log.txt` はそのまま残ります。
